# nodumbmode

скиллы для агентов, собранные из реальных проблем в проектах.

новый скилл появляется только после конкретного фейла. теоретические best
practices сюда не добавляются.

## что внутри

### scaling-check

[scaling-check](./scaling-check/SKILL.md) — проверяет, нужен ли общий источник
перед массовой правкой.

использовать, когда одно изменение приходится повторять в нескольких файлах:
при редизайне, миграции или унификации. результатом может быть токен, компонент,
адаптер или вывод, что общий слой пока не нужен.

### stuck-check

[stuck-check](./stuck-check/SKILL.md) — помогает заметить, что отладка встала, и
сменить источник данных вместо очередной правки на тех же предположениях.

использовать перед второй правкой без новых фактов, после двух неудачных
исправлений или одной ложной победы.

### changelog-discipline

[changelog-discipline](./changelog-discipline/SKILL.md) — ведёт changelog как
журнал решений: что поменялось, почему, как было раньше и что отвергли.

использовать после правок кода, при настройке changelog и перед релизом.

### decide-before-code

[decide-before-code](./decide-before-code/SKILL.md) — помогает понять задачу до
начала реализации и назвать дорогую ошибку заранее.

использовать для нетривиальных задач и запросов, где уже предложено решение, но
неясно, какую проблему оно решает. согласование нужно только для важных развилок,
необратимых решений и изменения скоупа.

### system-feedback

[system-feedback](./system-feedback/SKILL.md) — проверяет, понятно ли
пользователю, что произошло после действия и что делать при ошибке.

использовать для сохранения, удаления, отправки, загрузки, синхронизации и
экранов с пустым состоянием или ошибкой.

## как использовать

положить папку нужного скилла туда, где агент ищет скиллы, или передать путь к
его `skill.md` напрямую.

в `skill.md` лежат основные правила, в `references/` — примеры и подробности.
