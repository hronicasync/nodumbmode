# Как строить систему значений

Порядок из шести шагов. Каждый выведен из ошибки, которую он предотвращает.

## Содержание

- замерить существующее
- сжать значения по замеру
- посчитать цену до правки
- разделить значения по природе
- пометить исключения
- проверить систему на ней самой
- отдельно проверить типографику

---

## 1. Замерить существующее

**Не изобретать шкалу. Посчитать, что уже используется.**

```bash
# частота значений по типу
grep -rhoE 'padding\([0-9]+|cornerRadius: [0-9]+|spacing: [0-9]+' src/ \
  | grep -oE '[0-9]+$' | sort -n | uniq -c | sort -rn
```

Результат читается так:

- **лидеры частоты** — живые ступени, они уже работают
- **единичные значения рядом с лидерами** — шум, их можно сжать
- **крупные одиночки** — обычно вообще не из этой шкалы (см. шаг 4)

Выдуманная «красивая» шкала (4/8/16/32) сдвинет половину работающего интерфейса
без причины. Замер занимает минуты и обосновывает каждую ступень.

**Ошибка, которую предотвращает:** система, построенная на догадке, расходится с
реальностью и переделывается целиком.

---

## 2. Сжать по замеру, а не по ощущению

Убирать промежуточные значения — но проверяя частоту каждого.

Значение, которое выглядит промежуточным («что-то между 16 и 24»), может
оказаться третьим по частоте во всём проекте. Такое срезать нельзя: оно означает
отдельное решение, а не шум.

**Правило:** ступень остаётся, если она встречается заметно чаще соседнего шума.
Точный порог зависит от размера проекта, но разница обычно очевидна — лидеры
отрываются в разы.

**Ошибка, которую предотвращает:** срезанная живая ступень заставит десятки мест
сдвинуться без причины.

---

## 3. Посчитать цену до правки

Перед массовой заменой прогнать расчёт: сколько мест меняется, на сколько, где
самые крупные сдвиги.

```
# псевдокод расчёта
для каждого найденного значения:
    ближайшая ступень шкалы
    сдвиг = |ступень - значение|
сгруппировать по величине сдвига
```

Расчёт вскрывает то, что глазами не видно:

- слепое применение правила ломает часть случаев
- «однотипные» значения на деле разной природы
- сама шкала дырявая

**Ошибка, которую предотвращает:** массовая замена, которая ломает вёрстку в
местах, где значение было осмысленным.

---

## 4. Разделить по природе, а не по виду

Одинаково выглядящие числа часто имеют разный источник:

| Природа | Пример | Куда |
|---|---|---|
| Выведено из системы | отступ внутри карточки | в шкалу |
| Производное от другого элемента | «ширина иконки + зазор» для выравнивания | в именованную константу рядом с источником |
| Уникально для места | позиционирование всплывающего окна, поля вокруг изображения | оставить как есть |

Производные величины особенно коварны: они выглядят как обычные отступы, но
привязаны к размеру соседнего элемента. Оставленные числом, они разъедутся, когда
элемент изменится.

**Ошибка, которую предотвращает:** натягивание шкалы на то, что ей не
принадлежит, портит и шкалу, и место.

---

## 5. Пометить исключения

Каждое значение, не приведённое к системе, несёт объяснение рядом:

```
// 92 — не токен: позиционирование окна от верха экрана.
```

**Молча оставленное отклонение неотличимо от забытого.** Следующий проход либо
«доделает» его и сломает, либо будет бояться трогать.

**Обратная сторона правила:** если объяснение не пишется — значит, отклонение не
обосновано, и его надо приводить к системе. Требование написать причину работает
как фильтр.

---

## 6. Проверить систему на ней самой

После введения — прогнать проверку по коду самой системы.

Дизайн-система, не пользующаяся своими токенами; линтер с исключением на
собственный код; конвенция, нарушенная в её же описании — подрывают правило
целиком. Дальше на него никто не ссылается.

Единственное законное исключение: место, где значения **определяются**. Числа
где-то должны лежать физически.

---

## Отдельно про типографику

Если платформа даёт семантические стили текста (не пункты, а роли) — строить
шкалу на них, а не на числах. Причина не стилистическая: семантические стили
следуют системным настройкам размера текста, числовые — нет. Приложение с
захардкоженными кеглями игнорирует настройки доступности пользователя.

**Но:** фактические размеры надо **замерить**, а не взять из документации.
Платформы схлопывают соседние ступени по-разному, и две «разные» роли могут
оказаться одним кеглем. Это надо знать до того, как рисовать макет.
